# CLAUDE.md

Project memory for GH Panel: a small TypeScript Hono control panel that runs on a GitHub Actions Ubuntu runner and manages services (Tailscale, SSH, HTTP proxy, SOCKS5 proxy, 9router). See `README.md` for user-facing setup and secrets, and for the architecture diagrams (keep them in sync when the structure changes).

## Layout

- `src/index.ts`: entry point. `loadConfig()` -> `createServices()` -> `createApp()` -> `bringUpNetwork()` -> `serve()`.
- `src/app.ts`: `createApp()` composes the HTTP layer: basic auth (also on assets), `/assets/*` static files from `dist/public`, the route modules, and `app.onError` (renders `HttpError` and `HTTPException` as `{ error }` JSON).
- `src/config.ts`: `loadConfig()` reads the env once into a `Config` object (services get it via their constructor; nothing else reads `process.env`). `SECRET_ENV_VARS` lists what must never reach a child process.
- `src/lifecycle.ts`: `bringUpNetwork()` (Tailscale first, returns the bind address), `onListening()` (log public IP, run `autostart` services), `createShutdown()` (idempotent; stops controllable services, `process.exit(0)`).
- `src/routes/`: HTTP layer, no business logic. `services.ts` (`/api/services`), `server.ts` (`/api/system`, `/api/runner`, `/api/shutdown`), `pages.tsx` (`GET /`). Errors are thrown as `HttpError(message, status)`.
- `src/services/`: one class per service implementing `Service` (`types.ts`): `tailscale.ts`, `ssh.ts`, `proxy.ts`, `socks.ts`, `router9/` (service + `config.ts` for export/import). `index.ts` is the registry (`createServices`, `findService`); `network.ts` has `tailscaleStatus()` (cached 3 s, shared by all services), `tailscaleIp()`, `bindAddress(config)` and `displayHost(config)`.
- `src/system/`: `info.ts` (`getSystemInfo()`: server time, timezone, `os.uptime()`, per-interface traffic from `/proc/net/dev`), `runner.ts` (`getRunnerInfo({ refresh })`: public IP + geolocation via ipinfo.io, then ipwho.is, then ipify.org for IP only; cached 10 min; concurrent calls deduped).
- `src/shared/types.ts`: the API contracts (`ServiceView`, `RunnerInfo`, `SystemInfo`, `Traffic`, `SERVICE_ACTIONS`, ...). The only module both the server and the browser import.
- `src/lib/`: `exec.ts` (`run`, `exec`, `canConnect`, `sleep`), `errors.ts` (`HttpError`, `errorMessage`).
- `src/ui/Layout.tsx`: server-rendered HTML shell (`hono/jsx`): `<link>` to `/assets/styles.css`, `<script type="module">` for `/assets/app.js`.
- `src/ui/client/`: the browser app, client-rendered with `hono/jsx/dom` (own `tsconfig.json`). `App.tsx`, `components/` (`ServerCard`, `TrafficTable`, `ShutdownZone`, `ServicesSection`, `ServiceCard`, `Toast`), `api.ts` (typed fetch wrappers), `hooks.ts` (`usePoll`, `useClock`), `format.ts` (pure helpers), `toast.ts` (tiny store), `download.ts`.
- `src/ui/styles/`: CSS split by concern (`tokens`, `base`, `card`, `controls`, `server-card`, `toast`), bundled through `index.css` into `dist/public/styles.css`.
- `scripts/build.ts`: esbuild build of the server, browser app and CSS into `dist/`. `scripts/zip.ts`: bundles the project via `git ls-files` (`TODO.txt` and `dist/` are gitignored, so they are not included).
- `.github/workflows/panel.yml`: installs Tailscale, runs `npm ci`, `npm run build`, `npm prune --omit=dev`, then runs `npm start` as the **last** step. openssh-server and 9router are **not** installed by the workflow: the panel installs them on demand (see the install rule below).
- `TODO.txt`: personal task list, gitignored. Keep it updated (`[x]` when done, short notes underneath).

Stack: Node >=22.13 (`node:sqlite`), ESM, TypeScript 7, `hono` (server JSX + browser JSX DOM), `@hono/node-server`, `proxy`; dev: `esbuild`, `tsx`. No test suite, no linter.

## Commands

- Install + build: `npm ci && npm run build` (`dist/` is generated and gitignored; `npm start` fails until it exists).
- Dev: `cp .env.example .env`, then run `npm run dev:server` (`tsx watch` on `src/index.ts`) and `npm run dev:ui` (esbuild watch for the browser app and CSS) in two terminals. `.env` is read by `loadConfig()` via dotenv, so both pick it up. The browser needs a manual refresh after UI changes; `.env` changes need a restart.
- Production-like local run: `npm run build && npm run start:local` (loads `.env`). `npm start` never reads `.env`; on a runner the variables come from secrets.
- Run on a runner: `npm start` (needs `PANEL_USERNAME`, `PANEL_PASSWORD`, `TAILSCALE_AUTHKEY`, `PROXY_CREDENTIALS`; `TAILSCALE_HOSTNAME` is optional).
- Check: `npm run typecheck` (two projects: root = server + scripts, `src/ui/client` = browser). Run it and `npm run build` after every change.
- `.env` (real local values) is gitignored; `.env.example` is the committed template. Keep both in sync when a variable is added in `config.ts`.

## Layering rules (keep these true)

- Dependencies point down: `index` -> `app`/`lifecycle` -> `routes` -> `services`/`system` -> `lib`. Services and `system` never import `routes` or `ui`. Routes only translate HTTP to service calls.
- The browser imports nothing from the server except `src/shared/` (types and `SERVICE_ACTIONS`). Server code never imports `src/ui/client`.
- No `process.env` outside `config.ts` (and the env scrub in `router9/index.ts`). Pass `Config` into services.
- Errors in routes: throw `HttpError(msg, status)`; do not write per-route try/catch that builds JSON. Unknown errors become 500 and are logged as `[api] ...`.
- Service lookup by URL must go through `findService()` (own-property check), never `services[name]` directly.
- TypeScript is `erasableSyntaxOnly`: no `enum`, no namespaces, no constructor parameter properties; use `#private` fields and `import type` (`verbatimModuleSyntax`).

## Design rules (keep these true)

- **Tailnet only.** The panel (3000), sshd (22), proxy (3128) and socks (1080) bind to the Tailscale IP, never `0.0.0.0`. Use `bindAddress(config)` for panel/proxy/9router and `tailscaleIp()` for ssh.
- **Startup order.** `lifecycle.ts` starts Tailscale first (the panel itself listens on its IP), then the server listens, then each service with `autostart: true` starts (`proxy` and `socks`; `ssh` and `9router` are off until started from the panel). If Tailscale fails, exit with code 1 so the workflow fails; never fall back to all interfaces.
- **`BIND_ADDRESS`** overrides the bind IP for local dev only. In that mode Tailscale is skipped and `ssh` refuses to start, so a dev machine never gets users created or sshd started.
- **Service contract:** the `Service` interface in `src/services/types.ts`: `status() -> { running, info }`, `start(opts)`, `stop()`, optional `autostart`, `controllable: false`, `exportConfig() -> { filename, data }` and `importConfig(buffer)` (they add Export/Import buttons and the `GET/POST /api/services/:name/config` routes, registered before the `/:action` route). optional `isInstalled()` + `install()` (install on demand, see below). To add a service: write the class, register it in `createServices()`.
- **SOCKS5** (`socks.ts`): hand-written RFC 1928/1929 server on `node:net` (no dependency). CONNECT only, username/password auth only (no anonymous method), credentials from `PROXY_CREDENTIALS` split at the first `:` and compared in constant time, 10 s handshake timeout, host names resolved on the runner. Default port 1080, `?port=` override like the proxy; autostarts with it.
- **`tailscale` cannot be started/stopped in the panel** (`controllable: false`): no start/stop buttons, and the API returns 403. It has no `autostart` because `lifecycle.ts` starts it explicitly. Its machine name is `TAILSCALE_HOSTNAME` (optional, default `github-ubuntu`, validated as a DNS label in `loadConfig`), passed as `tailscale up --hostname`.
- **Host name, not IP, in the UI.** Cards show `displayHost(config)`: the MagicDNS name from `tailscale status --json` (`Self.DNSName` without the trailing dot), else the Tailscale IP, else `BIND_ADDRESS` in local mode. Sockets still bind to the IP (`bindAddress()` / `tailscaleIp()`); only the text shown (ssh command, proxy address, 9router URL, tailscale card) uses the name.
- **Tailscale card extras.** `status()` may return `details` (label/value rows) and `toggles` (`{ key, label, enabled, hint }`). Tailscale uses both: connection path (peers with recent traffic: `CurAddr` set = direct, empty with `Relay` = relayed; idle peers are reported as `(idle)`), home relay, and the `exit-node` toggle. A toggle is switched with `PUT /api/services/:name/toggles/:key` (`setToggle()`, works for non-controllable services; the key must be in the current `status().toggles`). The exit-node toggle runs `sysctl` (IPv4/IPv6 forwarding, left on afterwards) and `tailscale set --advertise-exit-node=<bool>`; the state is read from `tailscale debug prefs` (`AdvertiseRoutes`). It still has to be approved in the Tailscale admin console unless an `autoApprovers` ACL does it.
- **Panel icon** is `src/ui/assets/icon.svg` (+ `apple-touch-icon.png`, the same art without rounded corners at 180 px), copied to `dist/public` by `scripts/build.ts` and linked in `Layout.tsx`. Own artwork (service rows with status dots on an orange-to-aubergine gradient); do not use the Ubuntu or GitHub logos.
- **Install on demand.** `ssh` and `9router` implement `isInstalled()` + `install()` (both or neither; `isInstallable()` / `checkInstalled()` in `types.ts`). `ServiceView` carries `installable`, `installed`, `installing`; while `installed` is false the card shows only an **install** button (no start/stop/restart, no export/import). `POST /api/services/:name/install` (registered before `/:name/:action`) runs `install()` and keeps the request open until it ends; a per-route `installing` set rejects a second install and any start/stop while one runs (409). start/restart and the config routes return 409 for a service that is not installed. `isInstalled()` runs on every poll, so it must stay cheap (a file check; 9router caches `npm root -g`). `tailscale` and `proxy` are not installable (`installed` is always true).
- **SSH install** = `apt-get install openssh-server` through `sudo` with `RUNLEVEL=1` (so the packaged sshd is not started) and `DPkg::Lock::Timeout`; then the system `ssh.socket`/`ssh.service` are disabled (also again on every start) so port 22 stays free for the panel's own sshd. Refused in local mode (`BIND_ADDRESS`), like start.
- **SSH is off by default** (no `autostart`). Nothing is created or started until you press **start** on its card in the panel (after **install**).
- **SSH uses plain OpenSSH, not Tailscale SSH.** `tailscale up` must not get `--ssh`, which would intercept port 22 and bypass the password. `SshService` creates or updates a Linux user named `PANEL_USERNAME` with `PANEL_PASSWORD` (in the `sudo` group; sudo asks for the same password) and runs its own sshd (`/tmp/panel-sshd_config`, `AllowUsers` that user, no root login, `MaxAuthTries 3`). The workflow disables the system `ssh` service so port 22 is free. `PANEL_USERNAME` must be a valid Linux username.
- **9router is off by default** (no `autostart`). It is started from the panel by spawning its bundled Next.js server (`<npm root -g>/9router/app/custom-server.js`) directly with `process.execPath`, not the `9router` CLI (interactive menu, self-update, tray, detached children). Env: `PORT=20128`, `HOSTNAME=bindAddress()`, `DATA_DIR=<tmp>/panel-9router`, `INITIAL_PASSWORD=PANEL_PASSWORD`, random `JWT_SECRET` per panel process, `REQUIRE_API_KEY=true`. The panel's own secrets (`SECRET_ENV_VARS`) are stripped from the child env. Next renames the process to `next-server`, so match on that (not the script path) when checking for leftovers. `install()` runs `npm install -g 9router@latest --ignore-scripts` with `SECRET_ENV_VARS` stripped from the env (its postinstall only pre-fetches optional SQLite engines; it runs on `node:sqlite`).
- **9router config = one SQLite file** (`<DATA_DIR>/db/data.sqlite`, WAL). Export uses `VACUUM INTO` (safe while running) and drops `usageHistory`, `usageDaily`, `requestDetails`; the blob is gzip + AES-256-GCM keyed from `PANEL_PASSWORD` (scrypt). Import validates and patches a temp copy first, and only then stops 9router and swaps the file. 9router checks a stored bcrypt `password` in `settings` before `INITIAL_PASSWORD`, so import deletes that key (and forces `requireLogin: true`, `authMode: "password"`) to keep `PANEL_PASSWORD` the dashboard password. If 9router changes its storage layout, update `services/router9/config.ts` (`REQUIRED_TABLES`, `USAGE_TABLES`).
- **Public IP/location** is fetched server-side from the runner (the browser reaches the panel over Tailscale, so its own IP would be wrong). It is only served behind basic auth on the tailnet. Provider responses are validated (`net.isIP`, lat/lon regex). If every provider fails the API returns 502 and the card shows the error; the last known value is kept if one exists.
- **Traffic** comes from `/proc/net/dev`: `{ interfaces: [{ name, rx, tx, main }], total }`. Loopback and idle interfaces are left out; the internet-facing interface (default route, else `eth0`) is first with `main: true` (the UI highlights it), the rest are sorted by traffic. `total` sums every listed interface, so bytes that cross both a virtual interface (`tailscale0`, `docker0`, `veth*`) and `eth0` are counted twice; the panel says so. `traffic` is `null` off Linux.
- **Shutdown** (`POST /api/shutdown`) stops the controllable services and calls `process.exit(0)`. The run ends only because `npm start` is the workflow's last step, so don't add steps after it.
- **Secrets** come from env vars only. Never log them or commit `.env`. Exported 9router configs contain provider keys, so they must always stay encrypted.

## UI rules

- The page is a server-rendered shell (`Layout.tsx`) plus a client-rendered app. Server JSX uses `hono/jsx`, browser JSX uses `hono/jsx/dom`; that is why `src/ui/client` has its own `tsconfig.json` (`jsxImportSource`) and `scripts/build.ts` passes it per bundle.
- `c.html(<Layout />)` does not emit a doctype; `Layout` adds it with `raw("<!DOCTYPE html>")`. Without it browsers use quirks mode.
- JSX escapes text, so there is no `esc()` helper and no `innerHTML`. Never use `dangerouslySetInnerHTML` with server-provided text. Links built from server data must be checked (`isHttpUrl`).
- Styling lives only in `src/ui/styles/*.css` (no inline `<style>`, no inline style attributes). Add new rules to the file for their concern and import new files from `index.css`.
- Keep the browser app dependency-free apart from `hono`. Shared shapes go in `src/shared/types.ts`, and API calls go through `api.ts`, not `fetch` in components.
- The app polls: `/api/services` and `/api/system` every 5 s; uptime and server time tick locally every second between polls. Keep list items keyed so the DOM is patched, not replaced (text selection, e.g. the IP, must survive a poll).

## Testing without Tailscale

The sandbox or a dev machine usually has neither Tailscale nor sudo. To check bind behavior, run with `BIND_ADDRESS=127.0.0.2` and confirm requests to `127.0.0.1` are refused. Test 9router the same way: start it from the API, check `127.0.0.2:20128` answers and `127.0.0.1:20128` is refused, then round-trip `GET`/`POST /api/services/9router/config` (a fake `<tmp>/panel-9router/db/data.sqlite` with the required tables is enough to test export/import). Test the SOCKS5 service with `curl --noproxy '*' -x socks5h://u:p@127.0.0.2:1080 ...` (unset `http_proxy`/`ALL_PROXY` first, or curl may bypass it) or a raw socket client. Test the proxy by chaining it to the panel (`curl -x http://u:p@127.0.0.2:3128 -u admin:pass http://127.0.0.2:3000/api/services`). The browser app can be exercised without a browser by bundling it as an IIFE and running it in jsdom with a `fetch` bridge to the running server. The real `ssh` and `tailscale` paths can only be verified on an actual runner.
